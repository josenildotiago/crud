# Re-revisão da 3.2.0 — achados para a 3.2.1

**Data:** 29/07/2026
**Escopo revisado:** `63fcda9..v3.2.0`
**Veredicto:** nada a reverter, nada a retaguear. Os 8 achados da revisão final estão
fechados. A release publicada carrega 3 defeitos Important que valem uma 3.2.1.

Documento escrito porque estes achados vieram de uma revisão independente e não estão
registrados em nenhum outro lugar do repositório.

## Os três Important

### 1. Breadcrumb de `Show` e `Edit` gera href literal, sem interpolação

`src/stubs/react/Show.stub:30` e `src/stubs/react/Edit.stub:35`:

```
href: `/{{modelRoutePlural}}/{{modelCamel}}.id`
```

Template literal **sem** `${}`. Gerado no app de exemplo:

```
resources/js/pages/Item/Show.tsx:31:            href: `/items/item.id`,
resources/js/pages/Item/Edit.tsx:53:            href: `/items/item.id/edit`,
```

Clicar no breadcrumb do registro dá 404. O `tsc` não pega, porque é string válida.
Confirmado por inspeção direta dos dois arquivos gerados.

Anterior à rodada da 3.2.0, mas passou por baixo do commit `599d758`, cujo assunto era
justamente "Let --route reach the breadcrumbs of the generated components" — a verificação
daquela rodada olhou o breadcrumb do `Index.tsx` e não os outros dois.

**Observação de fundo, que vale mais que o conserto pontual:** os breadcrumbs escrevem URL
literal em vez de usar os placeholders de rota (`{{routeIndex}}`, `{{routeShowModel}}`) que
o próprio mapa de replacements já fornece. Foi essa duplicação que produziu o C1 desta
release. Unificar mata a classe inteira de defeito.

### 2. `upsert()` corrompe o `app-sidebar.tsx` quando o item já foi reformatado

`src/NavigationRegion.php:104-110`: a idempotência é `str_contains($line, $key)`, linha a
linha. Se o item virou multilinha, só a linha do `href:` é substituída e as irmãs ficam
órfãs.

Gatilho, sem nada exótico: (1) `getic:install configuracoes_sistema`; (2) `npm run format`
— script do próprio starter kit, `printWidth: 80`; (3) regerar a mesma tabela. Resultado
reproduzido:

```
    // crud:nav:start
    {
        title: 'Configuracoes Sistema',
    { title: 'Configuracoes Sistema', href: '/configuracoes-sistema', icon: CrudNavIcon },
        icon: CrudNavIcon,
    },
    // crud:nav:end
```

TSX inválido, gravado com `files->put()` sem pergunta e sem backup.

Aritmética do gatilho: a linha tem `48 + len(title) + len(href)` caracteres, então estoura
as 80 colunas quando os dois somam mais de 32. `items` (10) está longe;
`configuracoes_sistema` (42) estoura. **A troca de `List` por `CrudNavIcon` nesta release
encurtou a margem em 7 caracteres.**

**Conserto barato:** se o corpo entre os marcadores não for "um item por linha", devolver
`null` — esse caminho já existe e já imprime o trecho para colar à mão
(`InstallCommand.php`, ramo do `upsert() === null`). **Conserto completo:** ao casar a
chave dentro de um objeto multilinha, substituir do `{` de abertura até o `},`
correspondente.

### 3. O `eslint .` do usuário passa a falhar depois do install

`src/NavigationRegion.php:158-186` (`ensureImport()`) ancora no último import de uma linha,
ignorando agrupamento. No app real isso põe `lucide-react` depois de imports `@/`:

```
$ node_modules/.bin/eslint resources/js/components/app-sidebar.tsx
  18:1  error  `lucide-react` import should occur before import of `@/components/app-logo`  import/order
✖ 1 problem (1 error, 0 warnings)
```

Confirmado rodando. `npm run lint:check` (`eslint .`) é gate de CI do starter kit e quebra;
`npm run lint` (`--fix`) conserta.

**Correção idiomática, que mata dois coelhos:** fundir `List as CrudNavIcon` no
`import { ... } from 'lucide-react';` que já existe, em vez de acrescentar linha nova —
resolve o `import/order` e o import duplicado juntos. O `--fix` move a linha intacta, então
a idempotência do `str_contains` sobrevive.

## Minors

- **`CHANGELOG.md:22-34`**, a tabela de arquivos que o pacote escreve: diz `criado` para
  `routes/{model}.php` e para `resources/js/pages/{Model}/*.tsx`, mas os dois são
  **sobrescritos sem perguntar** (`write()` é `files->put()` puro,
  `GeneratorCommand.php:191-194`). Como a linha acima da tabela diz que o Controller
  pergunta antes, o leitor infere que o resto é inócuo — é o inverso. Falta também
  `resources/js/types/paginated.ts`, criado em `InstallCommand.php:1066-1068`.
- **`CHANGELOG.md:107-109`**: diz que `--route` não chegava "ao link da sidebar nem aos
  breadcrumbs", sem mencionar que agora também move o prefixo das rotas de API.
- **`README.md:300-315`**: o exemplo de rotas mostra `/products/bulk` (o stub gera
  `bulk-destroy`) e põe a curinga **antes** do bulk — a ordem que o comentário do
  `ModelRoutes.stub` diz não fazer.
- **`README.md:331-347`**: bloco de exemplo do `config/crud.php` velho
  (`layout_component => 'Layouts/AppLayout'` vs. `'Layouts/AuthenticatedLayout'` no arquivo
  real; sem `route_helper`, `navigation`, `api.prefix`, `api.middleware`).
- **`CLAUDE.md`**, pendência do `routes.stub` morto: está **incompleta** —
  `src/stubs/InertiaRoutes.stub` também é morto e não é citado (`grep -rn InertiaRoutes`
  fora do próprio arquivo devolve zero).
- **`.github/workflows/tests.yml:13-14`**: o comentário afirma que os jobs `lowest` provam
  o piso do constraint. Só vale onde o pacote é a restrição vinculante; para
  `symfony/console`/`symfony/process` não é (Laravel 12 já exige `^7.2`, o 13 `^7.4`), então
  `7.0.0` nunca é instalado em job nenhum. Falta também um `--prefer-lowest` em PHP 8.2.
- **Minor de comportamento:** o import do ícone só é garantido quando a região é criada
  (`install()`). Se o usuário trocar o ícone e um organizador de imports remover o
  `CrudNavIcon` órfão, a próxima geração reescreve `icon: CrudNavIcon` sem reintroduzir o
  import. Fecha chamando `ensureImport()` também no caminho do `upsert`.

## Fora do escopo revisado, mas levantado

- **`--api` gera PHP inválido.** Nada no pacote processa a sintaxe handlebars dos stubs de
  API, então `{{#each relations}}` vai literal para o arquivo do usuário
  (`ApiController.stub:59,75,89,104`, `ApiResource.stub:24`, `ApiRoutes.stub:56`). É flag
  documentada no README que não funciona.
- **`--api` colide nomes de rota.** `ModelRoutes.stub` nomeia `items.index`;
  `ApiRoutes.stub:19` faz `Route::apiResource('items', ...)`, que auto-nomeia `items.index`
  também. `php artisan route:cache` estoura.
- **`RichTextEditor` do `FormField.stub:310-313` é XSS armazenado latente:**
  `contentEditable` + `onChange(e.currentTarget.innerHTML)` gravando HTML cru, e
  `dangerouslySetInnerHTML` na leitura, sem sanitizar em nenhuma ponta. Hoje é exportado e
  **não usado** por `Create`/`Edit`. (O `dangerouslySetInnerHTML` de `Index.stub` é o
  `link.label` do paginator do Laravel: aceitável.)
- **A stack `heron` não é alcançável.** `buildViews()` só ramifica react/vue/blade e
  `STACKS` não a inclui, então `src/stubs/views/heron/` não é carregado por caminho nenhum.
  O `CLAUDE.md` manda mantê-la funcionando — confirmar com o dono se ela é acionada por
  outra via ou se está congelada como código morto.

## Semver

A 3.2.0 como minor é defensável, mas por um argumento diferente do que o CHANGELOG usa: **o
pacote não tem superfície de runtime.** Atualizar não muda comportamento de app implantado;
nada acontece até alguém rodar um gerador, que é ato explícito. Mudar a saída é "mudar a
próxima geração", não quebrar instalação de ninguém.

O argumento contra, que é real: o item 5 da API pública do `CLAUDE.md` ("estrutura dos
arquivos gerados que o usuário depois edita à mão") faz da troca `GET /{recurso}/index` →
`GET /{recurso}` uma quebra por definição do próprio projeto. Agravante: `routes/{model}.php`
e as páginas `.tsx` são sobrescritos **sem pergunta**, o que torna "regerar" destrutivo para
quem editou aqueles arquivos, no mesmo release em que o conteúdo deles mudou por inteiro.

**Recomendado:** não retaguear a 3.2.0. Na 3.2.1, (a) subir a troca de URL e a sobrescrita
silenciosa para o bloco "Leia antes de atualizar", e (b) fazer o item 5 do `CLAUDE.md` dizer
explicitamente se mudança de URL gerada conta como breaking, para a próxima decisão ser
mecânica em vez de opinativa.
